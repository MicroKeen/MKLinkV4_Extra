# SD 卡存档

图鉴（11 种鱼的捕获次数、最大尺寸）、总捕获数、最近一次捕获、当前装备与钓深，以及金币、装备解锁、特殊饵料库存、鱼库、船尾大鱼和游戏分钟保存到 SD 卡。开机先恢复，临时抛竿/战斗和输入状态重新初始化。本版本写入 v4，继续读取 v1/v2/v3。首次升级保留图鉴、金币、饵料库存、鱼获、容器和时间；竿、线组、漂的所有权和当前选择恢复为初始装备，当前饵料改为无限普通假饵、钓深到底。成功写入一次初始化标记后，新买的高级装备正常保存，不再重置。

- 行囊底部新增“存档”：旋转选中，短按保存。
- 默认从启动或最近一次保存请求起，每五分钟检查一次；有进度或装备变化才自动写入。
- 右上显示“存档中”，直到后台完成写入、同步、关闭和读回校验。最短显示 400 ms；这是 UI 的可见时间，不是加密耗时。随后显示“已存档”约 2.5 秒。
- 失败显示“存档失败”，保留未保存的数据；正常运行中的失败可手动重试，也会在下个周期重试。保存期间的手动请求会合并排队，完成后再保存最新快照。
- 开机无法读取 SD 卡、两个槽均损坏/被修改或未知格式时，不自动覆盖原文件。插好卡或备份处理异常文件后重新启动。手动按钮也不会强制抹掉异常旧存档。

## 文件名称与切换固件

板卡挂载逻辑盘 `3:`。SD 卡内文件位于独立目录：

```text
FishingGame_Saves_DO_NOT_DELETE/
  NorthWetland_Save_A_DO_NOT_DELETE.sav
  NorthWetland_Save_B_DO_NOT_DELETE.sav
  README_DO_NOT_DELETE.txt
```

`DO_NOT_DELETE` 即“请勿删除”。README 是 UTF-8 中文说明，A、B 两个文件都应保留。目录不放在临时文件、固件包或下载器工作目录里。PC 模拟器使用 SDL 的用户数据目录（可用 `FISH_SAVE_DIR` 覆盖），文件名是 `progress0.sav` / `progress1.sav`，与板卡密钥相互独立。

存档和当前固件文件名无关。切换到下载器或其他小游戏，再切回兼容版本，可恢复同一板卡上的数据。新的钓鱼固件必须保留 `app/fish_save_key.c` 的项目密钥、UUID 派生方式、此目录和 v1/v2/v3/v4 的字段顺序。不要重新生成项目密钥，不要把编译时间或固件哈希混入派生密钥。鱼种和装备索引是版本 1 固定映射；未来重排/增加数据应新增版本并实现迁移，不能复用版本号解释成另一套索引。

本次游戏固件不启用 USB MSC、不格式化 SD 卡，也不清理其他固件的数据。当前下载的 `mklink_sample_fire` 应用/公共驱动中未发现主动格式化调用；其脚本文件接口仍有删除能力。不能据此保证其他固件或下载器引导程序永不清卡。备份时复制整个存档目录，恢复到同一块板卡；格式化、电脑删除、损坏或丢失 SD 卡无法由本游戏阻止。

## 文件格式与保护

v4 每槽固定 **236 字节**：16 字节头、16 字节认证标签、204 字节密文。头仍为 `FSG1`，版本字段改为 4，包含长度和 64 位递增序号，头也参加认证。旧 v1 的 92 字节文件按原认证和 60 字节布局读取，不能仅修改版本号。字段显式按小端编码，不直接序列化 C 结构体。通过认证后检查装备范围/所有权、计数/尺寸、金币上限、饵料库存、鱼库容量、船尾重量和分钟范围，全部通过才应用。

| v4 明文偏移 | 长度 / B | 内容 |
|---:|---:|---|
| 0 | 60 | 原 v1 图鉴、装备和捕获字段，不重排 |
| 60 | 4 | coins，uint32 |
| 64 | 3 | 竿/线钩/浮漂的所有权位图 |
| 67 | 10 | 五种特殊饵料，uint16×5 |
| 77 | 110 | 11 种鱼库记录，每种 count:uint16、grams:uint32、value:uint32 |
| 187 | 1 | 船尾鱼种索引，11 表示空 |
| 188 | 2 | 船尾 size_mm |
| 190 | 4 | 船尾 grams |
| 194 | 4 | 船尾 value |
| 198 | 2 | 游戏分钟，0–1439 |
| 200 | 1 | 容器等级，0=小木桶/1=大木桶/2=储鱼箱 |
| 201 | 1 | 装备初始化世代，固定1；认证后的旧版记录视为0 |
| 202 | 2 | 保留零 |

读取 v1 时先按原布局验证，保留图鉴并补入当前特殊饵料五份；旧记录没有实物鱼获库存，不把历史次数兑换成金币。v2 新增经济状态，v3 新增容器等级，v4 使用原保留字节记录一次装备初始化，文件没有增大。v1/v2/v3 首次加载均恢复初始竿/线组/漂和所有权，保留其余已有进度；迁移先写非活动槽，成功前保留原槽，失败可重试。存在有效 v4 槽时，即使旧固件写了更大序号的 v3，也不再次初始化装备。旧固件不能读 v4；请先备份目录，切回本版本可正常读取。

使用 [RFC 5297 AES-SIV-CMAC-256](https://www.rfc-editor.org/rfc/rfc5297)。AES-128/CMAC 原语来自 HPM SDK 的 TinyCrypt 0.2.8 小型子集，不引入 TLS、网络协议、随机数生成器或完整密码库。SIV 允许在不依赖随机 nonce 的条件下做认证加密，避免复位导致 nonce 重复的风险。

项目密钥保存在固件中，以 AES-CMAC 和 HPM5301 OTP UUID 派生设备密钥。只读 UUID；不烧写 OTP、不锁调试口、不改变下载器用途。UUID 为全零/全 FF 时拒绝存档初始化。密钥不写入 SD 卡。直接修改密文、标签、序号或设备不匹配会被拒绝。

按作者明确授权，标准 demo 已公开原项目密钥，以保留同一板卡旧存档的兼容性。源码与完整开发归档也含该密钥；公开源码的玩家可以伪造认证存档。

这是离线文件防修改方案：有能力读取固件的人仍可能提取项目密钥并伪造存档；UUID 不是秘密。复制同一板卡上以前的有效存档可回退进度，删除整个目录可重新开始。要强防破解/回退需硬件密钥保护、可信计数器或服务器；本次没有启用这些措施。AES 的软件实现也不承诺抵抗物理侧信道攻击。

## 写入中断与性能

始终写非活动槽，读回一致后才更新 RAM 中的活动槽、序号和已保存快照。已有目标文件从头覆写，保留已分配的簇链，不先删除或重命名有效槽；写完调整长度并 `f_sync` / `f_close`。加载时独立检查两个槽，选择通过认证且序号最新的记录；最新槽写了一半时回退旧槽并显示“存档恢复”。

这能应对单个存档文件的撕裂写，不能保证廉价 SD 控制器或 FAT 元数据在任何掉电时都不损坏。拔卡/格式化不是支持的在线操作；SD 卡请在关机后更换。没有电源掉电中断和保电电路，不能保证最后一刻写入，因此最多会回退到上次成功存档。离开小游戏前手动保存并等待“已存档”。

文件 IO 只在启动恢复阶段和 RT-Thread `fishsave` 线程执行，draw handler 只读缓存状态。SD 使用 SPI1，LCD 保持 SPI0/DMA。工作线程静态栈 4 KiB；FatFs 是本应用独占的本地副本，支持 FAT/exFAT，代码页 437、ASCII 长文件名、512 字节扇区，无格式化接口。

MKLink 的原 SD 适配器不操作 GPIO 片选，小游戏沿用此行为。通用 `board.h` 的 `BOARD_SPI_CS_PIN` 指向 PA26，但本机 LCD 的 `ST7789_LED_SET` 也使用 PA26 作为背光。不能在 SD 初始化中重新配置此脚，也不能在片选回调里拉低/拉高它，否则每次 SD 读写都会导致屏幕背光闪烁。2026-10-14 已移除误加的 PA26 复用/输出初始化及片选切换，保留 LCD 对背光的控制；本次没有原理图，因此不推断 SD 的实际物理片选接线。

认证标签仍只有 16 字节；v4 相对 v1 增加的 144 字节用于新玩法状态，文件仍小于一个 512 字节扇区。2026-10-14 Windows 基准约 25.4 µs/次（10,000 次循环），不是 MCU 或 SD 耗时。新增 52,800 字节美术不属于加密成本。旧 `save-cost-report.json` 保留为 v1 历史报告；当前标准工程体积见其 `docs/validation.md`。硬件写入延迟和栈水位尚未测量。

## 验证

`tests/save_tests.c`：RFC 5297 A.1 标准向量、逐字节修改、短文件、错密钥、字段校验、v1/v2/v3真实认证迁移、一次装备初始化与重新购买后恢复、五分钟周期、计时回绕、异步期间状态变化、A/B 恢复、失败重试、损坏文件保护和手动按钮。

`tests/save_pc_tests.c`：真实文件写入、flush/commit/readback、重新初始化读取、截断最新文件后的恢复。

`tests/sd_backlight_tests.c`：编译板端实际 SD 适配器，以 GPIO 观测桩执行 128 轮命令/块写/块读，确认只使用 SPI1，PA26 的背光电平与复用不受影响。修复前，首轮片选回调就会拉低背光，测试失败；修复后通过。

`fish_game --save-smoke`：实际 RGB565/PFB 输出的按钮、存档中、成功、失败和异常提示。

本次不声称已完成 SD 卡拔插、实板断电实验或板端耗时测试；固件编译与本机测试通过后另行上板验证。

v3 容器更新：读取 v2（236 B，偏移200–203原为保留零）时所有金币、库存和鱼获原样保留，初始容器为小木桶；加载时按当前容器容量检查累计重量。扩容后的旧船尾鱼允许继续保留；空间足够时购买过程自动收入容器。规则见 [bucket-and-display-rack.md](bucket-and-display-rack.md)。
